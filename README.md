# M23 Cashew Advisor

A Khmer-language AI advisor for smallholder M23 cashew farmers in Cambodia — built for FirstWave's "AI in Motion" hackathon. Covers the full field lifecycle (planting → vegetative → flowering → fruit development → harvest) with Khmer text Q&A and photo-based pest/disease diagnosis, grounded in a physical Khmer agronomy reference book rather than general AI knowledge.

## Two builds, two purposes

**`prototypes/m23-advisor-prototype.html`** is a self-contained Claude artifact that calls Claude directly from the page (no API key needed) via the Artifact `sample` capability. It's genuinely interactive, but Anthropic's platform does not allow a `sample`-powered artifact to be shared publicly — so this can only ever be a **private** tool: for demoing to mentors, for farmer interviews (the farmer watches while the owner drives it signed into their own Claude account), or for pitch-video footage. It is not, and cannot be, the public submission link.

**`supabase/functions/cashew-advisor/index.ts`** is the real path to a publicly-usable product: deployed behind a Lovable-built frontend and a Supabase Edge Function, calling the Anthropic Messages API with a server-side key. Anyone can open the resulting URL with no account or consent step. See `docs/lovable-build-guide.md` for the exact setup.

Both builds share the same knowledge base and behavior rules, generated from `knowledge-base/kb-v2.json` by `python3 scripts/build_kb.py`, so they answer consistently. Only entries with status `ok` go into the prompt; entries marked `conflicts_with_book` or `not_found_in_book` stay out until they're fixed against the book. The shared rules:
- Replies are Khmer-first, with a short English gloss.
- Photo diagnosis is constrained to the pests/diseases actually documented in the source book — anything that doesn't match gets an honest "get it checked in person" answer instead of a guess.
- Content sourced from the physical reference book is treated as verified/credible; the one lifecycle stage the book doesn't cover (Fruit Development) is filled from external research and explicitly flagged as such wherever it's used.
- The flowering spray protocol and pest-chemical dosages carry a standing caution: transcribed from photographed book pages, not yet independently verified by a native speaker or agronomist, so the AI hedges on exact numbers rather than stating them with false confidence.

## Setup

1. Copy `.env.example` to `.env.local` and fill in the values:
   ```bash
   cp .env.example .env.local
   ```
2. Get an API key from [Google AI Studio](https://aistudio.google.com/) and paste it into `.env.local` as `GEMINI_API_KEY`. Without this the app still runs, answering from the knowledge base only.
3. For registration and the Telegram bot, also set `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` (Project Settings → API in your Supabase dashboard). The service role key is used server-side only — never expose it to the browser.
4. Run the development server:
   ```bash
   npm run dev
   ```

Database tables come from `supabase/migrations/20261101_init_schema.sql`; run it in the Supabase SQL editor before registering anyone.

## Status

Knowledge base v2.1 (built 2026-10-23): 123 entries, all checked against the book and used by the AI. The 12 v1 entries that had been flagged against the book are resolved: #4 was corrected to the book; nine were folded into the book entry that already answers the same question (their questions kept as match variants, recorded in `merged_from_v1`); #5 (day 15-20 flower risk) and #47 (termites) were removed because the book doesn't cover them. 28 entries carry `needs_verification` — their doses and figures still need a native speaker or agronomist to confirm, and the AI hedges on those numbers. Fruit Development beyond the book entries is still filled from external research and flagged as such.

## Demo mode

Open `https://m23-cashew-advisor.vercel.app/#demo` to fill the app with a sample farmer: a 6-year-old farm, a spray due today, and three seasons of sales for the Farm passport. The phone's own data is set aside and comes back when you tap **Exit** in the orange demo bar; **Reset** restores fresh sample data. Feedback taps during the demo are not sent to the sheet.
